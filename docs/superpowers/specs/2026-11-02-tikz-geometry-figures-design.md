# 几何图形 TikZ 重绘与同类题配图设计

日期：2026-11-02

## 背景与目标

当前整卷导入先由视觉模型给出 `figure_bboxes`，再调用独立定位接口细化坐标并保存裁剪图。代码只检查坐标是否合法、图片能否保存，不检查裁剪内容是否完整或是否属于当前题，因此坐标漂移时也会生成“成功”的错误图片。`几何2.jpg` 的导入说明继续依赖坐标裁剪无法达到准确配图的目标。

本次将几何图处理改为以下优先级：

1. AI 解析原题图形语义并生成 TikZ 源码；
2. 使用本机 TinyTeX / TeX Live 2026 的 `pdflatex` 编译；
3. 将原图与编译图进行对比，检查几何关系和题目一致性；
4. 只有重绘链路失败时才按需定位、裁剪并展示原图；
5. 同类几何题保留考点、错因、学段和题型约束，生成与新题干一致的新 TikZ 图，不要求外观与原图相同。

成功标准不是“LaTeX 能编译”，而是图中字母、点线关系、角度、长度及题干条件一致。视觉模型对比不能作为数学上的绝对证明，因此不通过或不确定时必须兜底，并允许人工校对确认。

## 已确认约束

- 当前编译器为 `/home/anna/.local/bin/pdflatex`，版本为 TeX Live 2026。
- 当前已安装 `standalone`、`pgf`（TikZ）、`amsmath` 及依赖，本机无需重复安装。
- 原坐标裁剪仅作兜底，不是每次导入的必经步骤。
- 成功路径不调用第二次远程图形定位，也不保存裁剪图，以减少导入时间和磁盘文件。
- 交付安装包采用“安装时自动配置 TinyTeX”，不将各平台 TeX 运行环境离线内置到安装包。
- 原题重绘允许省略山体、试卷背景等装饰信息，但必须保留解题所需的几何语义。
- 同类题可改变图形结构、条件和设问，但不得丢失目标考点或错点，且题干与新图必须一致。
- 本次不承诺用 TikZ 重绘所有函数图像、统计图或任意插画；这些类型继续使用现有图片兜底。几何图是主链路的首个支持类型。

## 方案比较

### 直接生成 LaTeX，仅检查编译

实现最简单，但编译成功不能发现漏点、错标、错误垂直关系等问题，不满足准确性目标，不采用。

### 结构化语义、TikZ、编译与视觉对比（采用）

一次生成同时产出图形语义和 TikZ，随后检查可编译性，再对比原图和渲染图。能覆盖较广泛的几何图，也保留可审计、可修改的源码。代价是增加模型调用和校验流程，通过延迟裁剪、按题批量处理、最多一次自动修复及编译缓存控制成本。

### 固定几何 DSL 与确定性绘图器

对预定义三角形、圆等图形可提供更严格的约束，但复杂图形覆盖有限，需要长期维护另一套几何建模和布局系统，超出本次范围。

## 总体架构与数据流

新增三个边界清晰的组件：

- `GeometryFigureService`：按题协调 AI 解析、编译、对比、自动修复和延迟兜底。
- `TikzRenderer`：校验 TikZ 安全性，包裹固定模板，调用 `pdflatex`，将 PDF 转为 PNG，并缓存产物。
- 图形数据模型：在 AI 输出、导入任务、数据库、错题展示和同类题之间传递语义、源码、有效图片及校验状态。

单题成功路径：

1. 首次视觉切题返回题干和 `figure_bboxes`。坐标只作为 AI 找图提示，不立即细化或裁剪。
2. 对包含几何图的题，调用一次几何解析，输入原页、题干和坐标提示，输出该题各图的语义规格与 `tikzpicture` 源码。
3. 本地编译所有 TikZ 图并转为 PNG。编译只在导入或生成时发生，Streamlit 刷新只读取 PNG。
4. 对比时使用原页和内存中的参考区域，不因对比而提前保存裁剪文件。
5. AI 对比通过后，将渲染 PNG 设为有效展示图，保存语义、源码和对比结果。
6. 校对页显示原图参考、重绘图和状态；确认入库后，错题本、复习、检测和同类题页面沿用同一有效图。

单题失败路径：

1. 解析、编译或对比失败后，允许一次带错误信息的自动修复；修复结果仍需重新编译和对比。
2. 仍失败时才调用 `locate_figures` 细化坐标并保存裁剪图。
3. 二次定位失败则使用首次 `figure_bboxes` 裁剪；首次坐标也不可用时显示完整原页。
4. 当前题标记需要校对，其他题继续导入，整卷任务不因单图失败而失败。

## AI 契约

### 原题几何解析

新增独立的结构化接口，不复用 `analyze_text` 或 `followup_question`。输入包括原页、当前题干、图形坐标提示和 K12 上下文，输出每幅图的：

- `kind`：目前主链路只接受 `geometry`，其他类型走兜底；
- `semantic_spec`：点、线、圆、角、标注及垂直、平行、共线、相等等关系；
- `tikz_source`：一个 `tikzpicture`，不包含完整文档 preamble；
- `assumptions`：为了省略装饰或处理示意图比例而作出的简化，不得改变解题条件。

模型必须优先保证语义，不要求按原图像素比例复刻。`几何2.jpg` 可简化山体轮廓，但必须保留 $P,Q,A,B,C$ 的相关位置、仰角 $\alpha,\beta,\gamma$、斜坡距离 $a$ 和垂直关系。

### 原图对比

对比接口接收原图参考区域、渲染图、题干和语义规格，返回：

- `passed`；
- `issues`：具体缺失或不一致项；
- `repair_instruction`：未通过时供一次自动修复使用。

检查字母与数值、点线从属、角的位置、垂直/平行/共线关系和题干一致性，不以像素相似度作为标准。模型返回不确定时按未通过处理。

### 同类题生成

新增结构化变式结果，包含新题干、可选新图语义和 TikZ，而不是只返回字符串。提示词输入原题干、知识点、错因、题型、难度、K12 元数据及原图语义，明确：

- 保留目标考点和学生需要训练的错点；
- 可以改变图形拓扑、点的名称、已知条件和设问；
- 不得为了复用原图而限制变式；
- 新图条件必须足以解答新题干，且不得与新题干矛盾。

生成后编译新图，再校验“新题干—新图—目标考点”一致性。失败时修复一次；仍失败则不返回该 AI 变式，库内召回结果不受影响。现有参考答案是另一独立步骤的约定保持不变，但参考答案生成必须能拿到新图语义，避免只看文字误答带图题。

## 数据模型与兼容

保留现有 `figure_paths`，其含义统一为“当前有效展示图路径”。新增与题目关联的 `figure_specs` JSON 列表，每项至少包含：

- `kind`；
- `semantic_spec`；
- `tikz_source`；
- `render_path`；
- `crop_path`；
- `validation_status`：`ai_passed`、`manual_passed` 或 `fallback`；
- `validation_issues`；
- `assumptions`。

成功重绘时，`figure_paths` 指向 `render_path`，`crop_path` 为空。兜底时，`figure_paths` 指向 `crop_path` 或完整原页由现有原图逻辑处理。`Segment`、导入任务 `segments`、确认入库、`Question` ORM、`QuestionOut`、API 响应和检测 `tested` 数据同步增加 `figure_specs`。数据库通过新 Alembic 迁移升级；旧题没有该字段时按空列表处理，现有 `figure_paths` 行为不变。

渲染产物采用内容寻址缓存，键包含 TikZ 源码、固定模板版本和编译器主版本。持久 `.tex` 与 `.png` 用于审计、页面展示和重新校对；临时 PDF、日志及辅助文件不进入题目数据。生成但尚未入库的同类题也可引用内容寻址产物，保存到错题本时保留对应规格和路径，不再只保存文字。

## 校对与展示

- 校对页并排提供原图参考和重绘图，显示 AI 对比通过、人工确认或兜底状态。
- 支持查看和编辑 TikZ，保存后重新执行安全检查、编译和对比；用户可明确接受人工确认结果。
- 自动对比未通过的重绘图不能静默替代原图。
- 错题本、今日复习和同类题检测继续通过 `figure_paths` 展示最终有效图，不增加页面刷新时的 AI 或 TeX 调用。
- 变式题保存到错题本时同步保存新图，而不是继承原错题图片。
- 图片使用原生 `st.image` 和简短 `alt`；不在 Markdown 中嵌入 LaTeX 文档或自行实现浏览器端 TikZ 解释器。

## TinyTeX 安装与打包

新增 `deploy/tinytex-requirements.txt`，声明 `standalone`、`pgf`、`amsmath` 等顶层宏包，由 `tlmgr` 解决传递依赖。`requirements.txt` 增加说明并引用该清单；TeX Live 不是 pip 包，不能伪装成 Python 依赖。PDF 转 PNG 继续使用项目已有的 PyMuPDF。

新增幂等安装脚本，支持：

- 自动安装 TinyTeX / TeX Live 2026 和清单中的宏包；
- `--check-only`，检查年份、`pdflatex`、宏包并编译最小 TikZ 图；
- 重复执行时跳过已满足的安装；
- 清晰的失败信息，不让缺少 TeX 导致整个应用无法启动。

配置增加 `PDFLATEX_PATH`。当前机器使用 `/home/anna/.local/bin/pdflatex`；部署启动器探测安装后的编译器并注入路径。安装打包流程在首启或安装阶段运行配置脚本，离线包不内置 TeX 的约定写入部署文档。缺少 TeX 时几何图功能进入裁剪兜底，其他功能正常。

## 编译安全与资源限制

AI 输出按不可信输入处理：

- 只接受受支持的 `tikzpicture` 内容，由应用固定 `standalone` 模板包裹；
- 拒绝外部文件读写、shell escape 和不在允许范围内的 TeX 宏；
- 使用参数数组直接启动进程，不经过 shell；
- 使用 `-no-shell-escape`、非交互和遇错停止模式，并限制 TeX 文件访问模式；
- 每次编译使用独立工作目录，设置超时、源码大小和输出大小限制；
- 缓存键不包含用户密钥或原始图片内容，日志不记录 `.env` 信息。
