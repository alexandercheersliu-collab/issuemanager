# 共享标准题库与错题录入复用设计

## 1. 背景与目标

当前录入只对“同一用户、同一原图 SHA-256”去重。不同学生录入同一道题时，仍会重复进行文本解析、几何识别与重绘，并分别保存解析和图片。现有公共种子题库只存在于 ChromaDB，没有可供个人错题直接引用的 SQL 标准题实体。

本设计建立全系统共享的标准题库，并将标准题内容与学生个人错题状态分离，达到以下目标：

- 教师预先发布整卷后，学生录入同卷错题能高比例命中并复用。
- 第一个学生录入的新题经校验后也进入标准题库，供后续学生复用。
- 精确命中时不重复调用文本解析、视觉解析或几何重绘。
- 所有学生录入都始终保存自己的原图，作为错因分析的原始证据；标准题库原图不向学生引用。
- 可独立使用的 AI 重绘图必须共享，避免重复生成；私有原图及其手写裁剪图不能共享。
- 学生删除自己的错题时同时删除私有原图；学生来源标准题在没有其他引用时一并清理。
- 教师可维护题型类别并在发布时指定题型；未指定时，AI 优先采用教师已发布的适用类别。
- Web 提供标准题库搜索、编辑和删除管理；Web 与 Mobile 的录入使用同一匹配和复用规则。

## 2. 已确认决策

- 标准题干、答案和解析在全系统范围复用。
- 学生生成的标准题通过自动校验后即可共享，不要求教师逐题审核。
- 教师发布的同题内容和题型优先于学生生成内容。
- 规范化题干精确匹配自动复用；语义相似匹配无论置信度多高都必须由学生确认。
- “本地题库”是服务端 SQL 与本地向量索引；“远程题库”是 Web/Mobile 通过服务端 API 访问同一共享库，不接第三方题库。
- 可以重构数据库，不要求保留旧表结构或运行时兼容读取。
- 学生原始照片、手写裁剪图、备注、错因和复习状态不向其他学生共享。
- 学生原图在个人错题存续期间始终保存，即使命中教师发布题也不省略；学生主动删除错题时一并删除。
- 标准题库原始图片只供教师管理，不向学生展示或引用；可独立使用的 AI 重绘图必须共享。
- 学生删除个人错题后，如果学生来源标准题已无任何剩余引用，则自动删除该标准题及其共享 AI 图和向量；教师/种子来源或仍有引用的标准题保留。
- 教师只能删除未被引用的标准题；admin 删除被引用标准题必须二次确认并列出受影响学生。
- admin 删除被引用标准题后，学生个人错题通过快照保留，不删除学生原图、复习记录或评论。

## 3. 方案比较

### 3.1 标准题与个人错题分表（采用）

新建标准题及共享资产模型，个人错题只保存标准题引用、个人状态和可选个人修改。能彻底减少重复解析与共享资源重复存储，权限和资源生命周期清晰。

### 3.2 跨用户引用现有 questions（不采用）

虽然改动较少，但题干、原图、个人备注和复习状态混在同一行，容易产生越权读取、删除联动和教师修改污染学生记录的问题。

### 3.3 命中后复制解析（不采用）

能减少 token，但仍重复存储解析和图片，教师修正也无法同步到既有引用，不满足长期维护目标。

## 4. 数据模型

### 4.1 canonical_questions

一行代表全系统唯一的一道标准题，核心字段包括：

- `id`
- `stem_markdown`：规范展示题干，不含个人作答内容。
- `normalized_stem`：用于诊断和检索的规范化题干。
- `normalized_hash`：规范化题干 SHA-256，全系统唯一。
- `analysis_markdown`、`answer`
- `knowledge_points`、`tags`、`difficulty`
- `question_type`、`chapter`
- `subject`、`grade`、`region`、`textbook_version`
- `origin`：`teacher` / `student` / `seed`
- `validation_state`：至少区分 `machine_validated` 与 `teacher_published`。
- `published_by`、`created_at`、`updated_at`

标准题对学生只读。学生编辑题面或解析时写入个人覆盖字段，不直接修改共享记录。

教师发布与既有学生标准题具有相同 `normalized_hash` 时，不新建重复标准题：教师字段覆盖或补全共享字段，来源升级为教师发布。教师原始页图只用于教师管理预览，既有学生个人引用仍使用各自原图。

只有具备完整题干、答案和解析的种子题才可作为直接复用候选；不完整种子数据可以保留用于检索，但不能以空解析创建个人错题。

### 4.2 question_assets

管理标准题资源，并按资源类型控制可见性：

- `canonical_id`
- `kind`：教师原始页图、AI 重绘图等。
- `visibility`：`teacher_only` / `shared`
- `storage_path`、`content_hash`、`mime_type`
- `is_preferred`：仅影响教师管理预览或有效图选择。
- `created_at`

教师原始页图一律为 `teacher_only`，不向学生展示或引用。可独立使用的 AI 重绘图可为 `shared`；依赖私有原图的 fallback 裁剪图不能进入共享资产。

学生原始照片不写入标准题资产。学生个人错题必须保存本次录入原图；由原图裁剪且可能包含手写痕迹的 fallback 图也按私有资源处理。

资源路径不包含学生用户名或个人错题 ID。图片经过解码重编码，去除 EXIF 等元数据。所有资源接口都要求登录，教师原始页图还需教师或 admin 权限，不开放匿名访问。

### 4.3 questions（个人错题）

现有表重构为学生个人记录，核心字段包括：

- `user_id`、可空 `canonical_id`
- `private_image_path` 及私有图形资源引用；拍照/整卷录入必须有本次原图。
- 个人标签、备注、错因、来源和来源文档
- 可选个人题干/解析覆盖字段
- 标准题快照字段及 `detached_reason`，供 admin 删除被引用标准题后保留个人错题。
- `match_method`：`exact` / `confirmed_similar` / `new` / `manual`
- 既有 SM-2 调度状态与时间戳

错题展示由服务层合并标准题、个人覆盖、标准题快照和私有资源。学生删除个人错题时删除其私有原图和私有裁剪图；学生来源标准题只有在删除后引用数为零时才连同共享 AI 图清理，不能因某个学生删除而移除仍被其他学生引用的标准题。教师/种子标准题只能走题库管理删除流程。

### 4.4 question_type_definitions

教师维护的题型类别：

- `subject`
- `name`
- `created_by`
- `enabled`
- `created_at`

对 `(subject, name)` 建唯一约束。教师发布题目时可以逐题指定类别。未指定时，AI 提示词提供当前学科下教师已发布的类别，要求优先选择确实适用的既有类别；没有合适类别时才允许生成新类别。

### 4.5 question_bank_audit

记录共享题库管理与生命周期操作：操作者（自动清理标记为 system）、标准题、动作、时间、变更摘要、受影响学生数和受影响个人错题 ID。admin 删除被引用标准题、普通教师编辑/删除和学生来源孤儿自动清理都纳入同一审计。

## 5. 匹配与录入流程

### 5.1 题干规范化

规范化用于匹配，不改变展示原文：

1. Unicode NFC（不使用会折叠上标等兼容字符的 NFKC）。
2. 复用现有 LaTeX 定界符归一化。
3. 去除已单独保存的外层题号。
4. 统一换行、首尾空白和连续空白。

不得删除或改写数字、变量、运算符、上下标及其他可能改变数学语义的内容。`normalized_hash` 由规范化结果计算并建立唯一索引。

### 5.2 匹配顺序

1. **个人原图哈希**：保持当前同一用户重复上传去重。
2. **题库原图哈希（仅用于匹配）**：原图完全相同且只对应一道标准题时可直接命中；对应多题时继续正常切题。命中后也不向学生引用题库原图。
3. **切题后的精确题干匹配**：按 `normalized_hash` 查询标准题库，自动标记复用。
4. **本地向量相似检索**：按学科、年级等上下文优先检索教师发布题，再检索学生机器校验题，返回候选及匹配依据。
5. **未命中新题**：才调用现有文本/视觉解析和几何流程。

精确命中自动进入待归档状态。相似命中必须展示候选题干、来源和解析摘要，由学生选择“引用此题”或“作为新题解析”；未作出选择前不得复用，也不因相似检索而省略后续确认。

向量检索只负责召回候选，不得将相似度作为自动等同证明。阈值和 Top-K 可配置，并通过独立评测集调整。

### 5.3 学生拍照录入

- 精确命中：不调用 `analyze_question`、`analyze_text` 或几何重绘；确认后创建个人错题引用。
- 相似命中：等待学生选择；确认引用后按复用路径归档，选择新题后才调用 AI。
- 未命中：执行现有 AI 流程；通过完整性和结构校验后创建标准题及个人错题。
- 无论命中学生题还是教师题，都保存本次学生自己的原图，并作为个人错题的展示原图和错因分析证据。
- 标准题库原始图片不提供给学生；学生只能使用自己的原图及允许共享的有效 AI 重绘图。
- 无论是否命中，都显示 `精确复用`、`相似待确认` 或 `新题解析` 状态，避免用户误以为重复调用了 AI。

学生新题进入共享库的最低校验包括：AI 结构校验成功、题目标记完整、题干与答案非空、解析非空。该校验代表机器可用性，不等同教师质量保证。

### 5.4 教师整卷预发布

教师导入界面增加明确的“发布到共享题库”目标。教师可在校对阶段逐题指定题型，确认后创建或升级标准题及题库资源，不要求在教师个人错题本生成一条错题。

教师导入已存在的标准题时复用现有题干和解析，教师明确填写的题型及修订字段优先。教师原始页图仅供教师管理；学生整卷导入仍创建个人错题并保存自己的原图，不获得发布权限。

### 5.5 并发与失败

- 数据库唯一约束保证同一 `normalized_hash` 只有一个标准题。
- 同进程可对相同哈希的首次解析做合并等待，避免并发重复 AI 调用。
- 跨进程即使 AI 调用已经发生，也必须在事务中复用已存在的标准题，不能覆盖教师已发布版本或重复创建题库资产。
- 单题匹配或解析失败不影响同批次其他题。
- 复用归档与新建归档都要保持幂等；重复确认不得新增个人错题。
- 任务临时副本在处理完成后清理；每个学生本次录入的私有原图和教师管理用原图按各自生命周期保留。

### 5.6 学生删除与孤儿标准题清理

- Web/Mobile 继续提供个人错题删除，服务层只允许删除当前学生自己的记录。
- 删除事务先锁定目标个人错题及相关标准题，再删除个人记录并收集私有原图、私有裁剪图和候选标准题 ID。
- 对每个候选标准题重新统计剩余引用：仅当 `origin=student` 且引用数为零时，删除标准题、共享 AI 重绘图资产和对应向量，并写自动清理审计。教师发布、已升级为教师来源或种子来源的标准题不自动删除。
- 若仍有任何学生引用，标准题和共享 AI 重绘图必须保留；删除者自己的私有图片仍被删除。
- SQL 提交后删除私有文件及孤儿标准题文件，路径必须限制在对应数据目录内。文件删除失败记录可重试清理任务，不恢复已删除的 SQL 记录。
- admin 已解除引用的快照记录没有 `canonical_id`，学生以后删除该记录时只清理个人记录和私有图片。

## 6. 服务与 API

### 6.1 共享服务

新增标准题仓储和匹配服务，负责规范化、精确查询、相似候选、创建/升级标准题及复用归档。`PhotoEntryService`、`DocumentService` 和 `QuestionService` 必须调用同一服务，不在 Web 或 Mobile 各自实现匹配逻辑。

### 6.2 任务契约

拍照和整卷任务条目增加：

- `match_status`
- `canonical_id`
- 相似候选列表
- 最终复用/新建结果
- 可共享的有效 AI 重绘图引用

现有确认接口增加相似候选解决选择；精确命中无需额外确认。任务 API 只返回当前用户可查看的私有资源或允许共享的有效图，不返回标准题库原始图片。

### 6.3 题库与题型接口

- 学生只能读取录入任务返回的匹配候选、标准题内容及允许共享的有效图。
- 教师可搜索、发布、修订标准题和维护题型类别。
- 学生不能修改或删除共享标准题，也不能维护教师题型。
- 相似确认接口校验任务属主、候选集合和当前任务状态。
- Web 直接调用服务；Mobile 只通过 REST 获取相同录入结果，不增加题库管理入口。

`QuestionOut` 的题面、解析、图片等展示字段保持统一，由后端完成合并；可额外暴露 `canonical_id` 和 `match_method` 供界面标识复用。个人错题展示原图始终取本记录私有原图。

### 6.4 Web 标准题库管理

Web 新增仅教师/admin 可见的“标准题库”管理页：

- 按关键词、学科、年级、教材、题型、来源和引用数搜索，支持分页；语义搜索只作为检索方式，不改变权限。
- 列表展示题干摘要、题型、来源、更新时间、引用学生数；详情展示完整题干/解析及教师原始图片。
- 教师可编辑题干、答案、解析、知识点、题型和上下文。编辑后更新规范化哈希与向量索引；若哈希与其他标准题冲突则拒绝保存并提示。
- 教师修订会反映到没有个人覆盖的既有引用；学生个人覆盖、私有原图和复习状态不变。
- 列表和详情均提供删除入口，但只有满足下述引用约束才允许执行。

Mobile 不提供标准题搜索、编辑或删除管理功能。

### 6.5 删除与二次确认

- **普通教师**：只能删除引用数为零的标准题。服务层在事务中重新检查引用数；已有引用时返回 409，不因前端隐藏按钮而绕过检查。
- **admin 影响预览**：删除被引用标准题前，先请求影响预览。Web 二次确认对话框列出受影响学生的用户名、个人错题 ID 和数量，并明确说明将解除共享引用但保留个人快照。
- **admin 二次确认**：确认请求携带标准题 ID、预览时引用数和明确确认短语。若引用数已变化，则拒绝执行并要求重新预览，避免影响列表过期。
- **删除事务**：为每个引用记录保存标准题当前题干、答案、解析和元数据快照，将 `canonical_id` 置空并记录 `detached_reason=admin_delete`；学生原图、个人覆盖、复习记录、评论和检测记录不变。随后删除标准题及其题库资源并写审计记录。
- **索引一致性**：SQL 是权威来源；事务成功后删除对应向量。向量删除失败进入可重试的对账流程，不能因此恢复已删除的 SQL 标准题。
- **权限来源**：admin 使用现有独立管理员权限判断，不把普通 `teacher` 角色等同于 admin。

## 7. 检索与存储

- SQL 保存标准题权威内容和个人引用关系。
- ChromaDB 保存标准题向量，只用于相似候选召回；标准题 SQL ID 是向量文档的稳定身份。
- 标准题修订时同步更新向量；个人备注和复习状态不进入共享向量。
- 现有种子题库迁移为 SQL 标准题加向量索引，不再以 ChromaDB 作为唯一数据源。
- 本地嵌入仍可作为默认；配置远程嵌入时只改变向量计算位置，不改变复用确认规则。

## 8. 隐私与安全验收边界

- 学生私有原图不能通过标准题资源 ID、猜测路径或教师查看学生列表以外的接口被其他学生读取。
- 教师可以查看既有业务允许的学生错题，但该权限不意味着其他学生可以读取彼此原图。
- 学生来源标准题不得包含学生备注、手写裁剪图、用户名或个人复习字段。
- 标准题库原始图片只允许教师/admin 在 Web 管理页读取，不向学生返回资源 ID 或 URL。
- AI 重绘图只有不依赖私有原图文件时才可共享；fallback 裁剪图默认私有。
- 教师原图必须经过明确发布动作才进入题库管理，不因上传临时文件就自动入库。
- 日志和遥测不记录完整私有图片或学生个人备注。

## 9. 可观测性

按匹配方式记录：命中次数、相似确认率、误匹配纠正、跳过的文本/视觉/几何调用次数，以及共享有效图带来的重复生成和存储节省。个人错题存续期间学生原图始终保存，不把该部分存储量列为可削减指标；学生主动删除后的正常清理单独计数。远程模型 token 只有在提供商返回真实用量时才记录实际值，否则报告“调用次数节省”，不伪造 token 数字。

题库搜索不产生审计事件；编辑、删除和删除影响快照必须可追踪。

## 10. 数据迁移与兼容范围

使用一次 Alembic 重构创建新表并改造个人错题表，不保留旧表双读或旧 API 内部格式适配。演示数据、备份导入、种子题库和测试夹具同步升级。

开发数据迁移按规范化哈希合并标准题；教师来源优先。私有原图始终绑定原个人错题，不能因合并标准题而变成题库资产。

## 11. 测试与验收

### 11.1 单元与服务测试

- 规范化稳定性及数学语义保护。
- 精确命中自动复用，文本/视觉/几何解析调用为零。
- 相似命中未确认不复用；确认后才创建引用。
- 未命中创建机器校验标准题；首位学生原图保持私有。
- 命中学生题或教师题时都保存并使用命中者自己的原图，不返回题库原图。
- 教师题型优先级、指定值覆盖和 AI 类别候选提示。
- 同题并发只产生一个标准题，各自个人错题正确归档。
- 重复确认幂等，单题失败隔离，资源权限正确。
- 教师修订同步到未覆盖的个人引用，个人覆盖不受影响。
- 学生只能删除自己的错题；删除后私有原图和私有裁剪文件不存在。
- 最后一名学生删除学生来源题时，标准题、共享 AI 图和向量一并删除；仍有其他引用或教师/种子来源时保留，其他学生仍可复用共享 AI 图。
- 学生不能搜索管理接口、编辑或删除标准题；教师可搜索和编辑。
- 教师删除未引用题成功，删除被引用题返回 409。
- admin 删除被引用题必须完成影响预览和二次确认；确认列出准确学生集合，引用数变化时拒绝过期确认。
- admin 删除后个人题干/解析快照、私有原图、复习记录和评论保留，共享题与向量删除且审计完整。

### 11.2 检索评测

建立包含完全同题、空白差异、LaTeX 差异、轻微 OCR 错误、仅数字变化、同知识点不同题的评测集。分别报告精确匹配准确率、相似候选召回率和误匹配率；相似阈值不能只在同题样本上调整。

### 11.3 端到端验收

- 教师发布整卷 → 学生拍照选择错题 → 命中复用 → 错题本可见且保留学生原图。
- 学生 A 新题录入 → 学生 B 精确命中 → B 复用解析及共享 AI 图且只能看到自己的原图。
- 学生 A 删除自己的错题 → A 的私有图片删除；B 仍引用时标准题和共享 AI 图保留；B 也删除后孤儿标准题清理。
- 相似候选在 Web/Mobile 均需确认，选择新题后正常调用 AI。
- 教师指定题型在两端归档结果中一致。
- Web 教师完成题库搜索、编辑和未引用题删除。
- Web admin 删除被引用题时看到受影响学生列表并二次确认；删除后学生错题和原图仍可访问。
- 运行全量后端测试、Web E2E、Mobile E2E、Mobile lint/build 和迁移测试。

## 12. 非目标

- 不接入外部第三方题库。
- 不新增班级或师生绑定体系。
- 不允许学生原图跨学生共享，也不向学生引用标准题库原始图片。
- 不以减少存续错题的学生原图存储为目标；个人错题存续期间原图必须保留，主动删除后才清理。
- 不让高置信相似题绕过人工确认。
- 不在 Mobile 增加标准题库管理功能。
- 不在本期引入标准题多人协同审核、复杂版本分支或公开匿名题库。
- 不承诺所有同题都能命中；切题或 OCR 严重错误时仍可能按新题解析。
