# Mobile 现有录题流程后端能力对齐设计

日期：2026-11-12

## 背景

高中数学题支持改造集中增强了 Streamlit 网页版和后端服务：多图切题、疑似错题预判、候选确认、去重、K12 上下文、几何图重绘/校验/兜底、整卷校对以及统一入库。Mobile 的现有两个入口仍使用较早的处理链路：

- “拍照录题”调用整图 `/questions/analyze`，没有多图候选确认，且同步入口未使用图片去重。
- “整卷导入”只接受图片并在客户端合成 PDF，校对仅支持删除；没有直接提交 PDF/DOCX、逐页图片或单题重新解析。
- Mobile 类型和页面没有使用 `figure_paths` / `figure_specs`，入库后的详情、复习和同类题检测无法展示新增图形。
- Mobile `splitStem` 只识别 `\n\n---\n\n`，而整卷入库使用 `### 题目` / `### 解析`，导致题面与解析不能正确分离。

目标是在**不增加或扩展录题入口**的前提下，让现有 Mobile 拍照与整卷流程使用与网页版一致的后端能力，并保证入库后的内容可以正确使用。

## 已确认约束

- Mobile 是学生端，操作简单优先。
- 保留现有“拍照录题”和录题页底部“整卷导入”两个入口，不增加文字录入、导航 Tab 或其他录题方式。
- 不提供文字校对、LaTeX/TikZ 源码编辑、字符位置拆分或教师端高级图形编辑。
- 不新增 Mobile K12 表单。本次使用与网页版一致的默认上下文：数学、10 年级、上海、沪教版。
- 多图、候选勾选、进度和结果展示均在现有页面内完成；只有识别出多题时才要求学生选择。
- 图形由服务端自动重绘、校验和兜底，Mobile 只展示最终有效图及必要的准确性提示。
- 注册时采集学生基本信息可作为后续扩展，用注册资料替代默认上下文；不属于本次范围。

## 非目标

- 不改变底部主导航或新增 Mobile 页面入口。
- 不实现 Mobile 手动文字录题。
- 不移植网页版的题干/解析编辑、合并、拆分、TikZ 编辑或人工图形确认控件。
- 不改变 AI 提示词、TikZ 安全策略、SM-2 调度或数据库表结构。
- 不强制历史数据重新解析或补图。

## 方案选择

采用“共享录入服务 + 双端薄界面”：

- 把 Streamlit 拍照页中的切题计划、候选整形、默认勾选、确认入库、失败隔离和结果整形抽到后端服务。
- Web 直接调用共享服务；Mobile 通过 REST 调用同一服务，不维护另一套切题与入库规则。
- 整卷任务继续复用 `DocumentService` 和现有 documents API，只补 Mobile 当前缺少的调用与只读资源接口。

不采用 Mobile 专用编排，因为两套规则会再次漂移；也不把所有拍照强制并入整卷校对，因为单题拍照应保持简单、自动入库。

## 共享拍照录入服务

新增后端 `PhotoEntryService`，复用 jobs 表和现有后台线程执行模式，不依赖 Streamlit 或 React。

### 创建与切题

输入为同一现有拍照入口选择的一张或多张图片、可选标签/备注及录入上下文。服务负责：

1. 校验并持久化任务输入，创建 `photo_entry` 任务。
2. 后台逐图调用 `segment_page`。
3. 每张图切出至少两题时生成候选；候选包含稳定 ID、来源图、题号、题干摘要、`likely_wrong` 和图形坐标。
4. 单题、空结果或切题异常进入整图回退，不重复调用切题接口。
5. 有候选时任务进入待确认状态；疑似错题默认选中。没有候选时直接处理回退图片，无需学生额外确认。

### 确认与入库

确认请求提交候选 ID，不接受客户端传来的题干或文件路径。服务从任务中重新读取候选并执行：

1. 对选中候选调用 `analyze_text_and_save`，同一原图的多题共享持久化图片。
2. 对回退图片调用 `analyze_and_save_dedup`，复用同图记录并跳过重复 AI 调用。
3. 沿用现有 K12 上下文、图形重绘/校验/兜底、向量索引和小题聚焦逻辑。
4. 每项记录进度；单项失败不影响其他项。
5. 任务完成后返回成功、重复和失败明细；重复确认返回原结果，不重复入库。

### Web 接入

`frontend/pages/tutor.py` 保留现有页面结构与交互顺序，但不再自行实现切题和入库编排。页面通过共享服务创建任务、读取候选、提交选择并轮询状态。现有 E2E 所见的“从图中识别出”“确认录入”“已自动归档入错题本”等行为保持不变。

## API 契约

新增拍照任务端点，建议归入独立 `photo-entry` 路由：

- `POST /api/photo-entry/jobs`：多图上传，创建任务并返回 `job_id`。
- `GET /api/photo-entry/jobs/{job_id}`：返回阶段、候选、回退数量、进度、结果和错误。
- `POST /api/photo-entry/jobs/{job_id}/confirm`：提交候选 ID；无候选任务不允许调用。

任务响应使用明确的 `phase`：`planning`、`review`、`importing`、`done`、`failed`。候选 ID 在任务内稳定，确认按 ID 而不是数组下标。所有端点沿用现有 JWT、文件类型/大小、年级和按用户限流规则。

整卷继续使用：

- `POST /api/documents/import`：直接提交一个 PDF/DOCX，或按页序提交多张图片。
- `GET /api/documents/{job_id}/segments`：读取进度与校对列表。
- `DELETE /api/documents/{job_id}/segments/{index}`：删除误切题。
- `POST /api/documents/{job_id}/segments/{index}/reanalyze`：重新解析当前题。
- `POST /api/documents/{job_id}/confirm`：幂等确认入库。

Mobile 文档上传显式传递 `use_default_context=true`，由后端共享默认值填充未提供的 K12 字段；既有 API 调用方未传该标志时的行为不变，Mobile 不在 TypeScript 中复制一套默认值。

## 内容与图形资源

### 题面与解析

把题面/解析拆分规则放到后端共享模块，同时支持：

- 拍照/切题库：`\n\n---\n\n`；
- 整卷入库：`### 题目\n...\n\n### 解析\n...`；
- 无分隔符的旧数据：全文作为题面，解析为空。

`QuestionOut` 增加只读 `stem` 和 `analysis` 字段，保留 `content_markdown`。Mobile 详情和复习优先使用这两个字段，不再自行猜测格式。同类题检测响应也提供已拆分的题面，避免另一处重复解析。

### 鉴权图片读取

不接受客户端提交任意服务器路径。增加按所属关系解析的只读端点：

- `GET /api/questions/{question_id}/figures/{index}`：读取已入库题的有效图。
- `GET /api/documents/{job_id}/segments/{index}/figures/{figure_index}`：读取整卷校对中的有效图。
- `GET /api/documents/{job_id}/pages/{page}`：读取当前任务页图，用于无有效图时回退。
- `GET /api/detection/{log_id}/figures/{index}?token=...`：读取当前检测题的有效图，包括尚未入库的生成题。检测发起响应为每幅图返回短期签名令牌；因为生成题尚未入库且检测日志没有图形路径字段，令牌使用现有认证密钥绑定用户、日志、图序和真实路径，不新增数据库列。

服务端验证当前用户、资源所属关系和索引，并从已有记录或已验签的检测令牌解析真实路径。缺失资源返回 404，其他用户的资源返回 404，不能泄露路径或文件是否存在。

Mobile 封装统一的鉴权 blob 图片组件，负责 object URL 的释放。展示顺序与 Web 一致：优先当前题有效图，完整原页仅作回退或按需查看；检测题在题文附近显示对应图。`validation_status="fallback"` 时只显示简短准确性提示，不展示源码。

## Mobile 现有页面调整

### 拍照录题

- 文件选择仍位于现有拍照入口，允许一次选择多张图片并预览。
- 标签和备注保留现有位置；不增加 K12 控件。
- 切题中显示轻量进度；仅多题候选出现时显示勾选列表，疑似错题默认选中。
- 确认后显示逐题进度；完成页显示入库数量、重复提示和失败摘要，并保留“去错题本看看”。
- 任务 ID 持久化，切走或刷新后恢复未完成的切题/入库任务。

### 整卷导入

- 保留录题页底部现有入口。
- 同一文件选择器接受一个 PDF/DOCX 或按页序多张图片；多图直接上传，不再要求先合成 PDF。
- 保留现有任务恢复、进度、删除和确认入库；增加现有 API 已支持的“重新解析”操作。
- 校对卡片展示题干摘要、页码、最终图/页图、失败状态和简短复核提示。
- 完成页显示入库与跳过数量，跳过原因放入可展开详情。

### 详情、复习与检测

- 使用后端 `stem` / `analysis` 正确展示两种入库格式。
- 在现有详情弹窗、复习题面和检测面板中显示有效图，不增加新页面或高级操作。

## 默认上下文与未来扩展

本次 Mobile 请求使用数学、10 年级、上海、沪教版，与网页版初始值一致。默认值应在共享后端配置/常量中定义，Web 和 Mobile 使用同一来源，避免分散修改。

后续注册流程可采集学科、年级、地区和教材版本，保存为用户偏好；录题时优先使用用户偏好，未设置时才回落默认值。该扩展需要独立的用户资料契约和隐私评估，本次不实现。

## 错误处理与安全

- 文件为空、类型不支持、大小超限和年级非法时，在创建任务前返回明确错误。
- 单图切题失败回退整图；单题解构或图形处理失败只影响当前项。
- 轮询的瞬时网络失败保留任务并继续，连续失败允许学生主动放弃本地任务视图。
- 所有任务查询、确认、重新解析和资源读取按用户隔离。
- 不在客户端持久化服务器文件路径，不把任务图片挂载为公开静态资源。
- 已确认任务不允许继续编辑或重复入库。

## 测试与验收

### 后端与 Web

沿用现有 pytest，先写失败测试再实现：

1. 多图计划、候选稳定 ID、疑似错题默认选择和单图回退。
2. 候选确认、K12 透传、去重、逐题失败隔离、进度和幂等。
3. 两种内容格式的统一拆分及旧数据兼容。
4. PDF/DOCX/逐页图上传、删除、重新解析和确认入库 API。
5. 题目、文档和检测图片的属主校验、索引边界及缺失资源。
6. Web 现有拍照与整卷测试、E2E 全流程保持通过。

### Mobile

不新增测试框架。复用现有 Playwright，以学生视口和 MockProvider 验证：

1. 现有拍照入口上传多图 → 候选确认 → 入库 → 错题本可见。
2. 单图自动回退、重复上传和失败提示。
3. 现有整卷入口上传 PDF/多图 → 删除/重新解析 → 确认入库 → 跳过明细。
4. 整卷题在详情和复习中正确分离题面/解析。
5. 有效图在详情、复习和检测中通过鉴权接口显示。
6. 刷新后恢复未完成任务。

执行 `npm run lint`、`npm run build`、完整 pytest、Web/Mobile E2E 和全项目 Ruff。真实模型的识别质量与 TikZ 语义准确性仍需使用既有几何样例人工验收，不能由 MockProvider 测试替代。

## 完成标准

- 不新增任何 Mobile 录题入口或高级编辑控件。
- 两个现有入口与 Web 使用相同切题、去重、K12、图形和入库规则。
- 单题保持简单自动入库，多题只在必要时要求勾选。
- 整卷与拍照题在 Mobile 详情、复习和检测中均正确显示文字与有效图。
- 所有自动化检查和上述真实操作链路通过。
